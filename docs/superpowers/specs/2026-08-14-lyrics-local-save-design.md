# HY Desktop · 歌词作品本地保存

日期：2026-08-14  
状态：已确认，待实现  
前置：[MiniMax 歌词智能体](./2026-08-14-minimax-lyrics-agent-design.md)

## 1. 目标

用户在歌词创作结果区确认后，把当前**歌名 / 风格 / 歌词**保存到本机一个作品文件夹。默认落在应用导出目录，保存前可改文件夹名。不调用 MiniMax 出歌 API。

## 2. 非目标

- MiniMax 音频生成或下载
- 自动保存（生成成功不写盘）
- 覆盖已有作品文件夹
- 把上传的小说全文写入导出目录
- 网页版保存（仅桌面端）

## 3. 交互

1. 生成成功后，结果区出现「保存到本地」（与复制按钮并列）。
2. 用户可先改歌名、风格、歌词，再点保存。未生成或三项都空则 toast，不弹对话框。
3. 弹出另存为：父目录默认是设置里的导出目录（未配置则为 `下载/HY`），默认文件夹名是净化后的歌名；用户可改名或换目录。取消则不写盘。
4. 确认后才创建文件夹并写入三个文件。成功 toast 显示最终文件夹路径。
5. 复制歌词 / 风格 / 全部保持不变。

## 4. 文件夹布局

以歌名 `雨夜离开` 为例：

```
{导出目录}/雨夜离开/
  README.md
  style.txt
  lyrics.txt
```

目标路径已存在（无论是目录还是文件）时，依次尝试 `雨夜离开_2`、`雨夜离开_3`，直到新建成功。不覆盖、不写入已有路径。

### 4.1 README.md

UTF-8，无 BOM，换行 `\n`。只含当前表单元数据，不含上传文档正文：

```markdown
# {歌名}

- Type: {创作类型标签}
- Language: {歌词语言标签}

## Prompt

{提示词，空则 (empty)}

## Source

{上传文件名，无则 (none)}
```

### 4.2 style.txt / lyrics.txt

结果区当前文本原样写出（UTF-8，无 BOM，`\n`），便于直接贴到 MiniMax。允许其中一项为空，但不能三项都空。

## 5. 文件夹名

与转写输出 stem 相同规则：

- `\ / : * ? " < > |` 与控制字符、NUL 换成 `_`
- trim，去掉末尾 `.` 与空白
- 最长 96 字符
- 空歌名或净化后为空 → `untitled-lyrics`
- 另存为若带扩展名（如 `.md` / `.txt`），去掉最后一段扩展名后再当文件夹名

返回路径的父目录必须通过现有 `is_path_safe`（导出目录、下载、文档、AppData、安装目录等）。不安全则拒绝，不写盘。

## 6. 实现边界

| 单元 | 职责 |
|---|---|
| `ai-lyrics-core.js` | 净化文件夹名、组装 README / 三文件内容（纯函数，可单测） |
| `ai-lyrics-ui.js` | 保存按钮、取导出目录、另存为、调用写盘、toast / i18n |
| Rust 新命令 `save_lyrics_project` | 校验路径、创建唯一空目录、写入三文件；任一步失败则删除该新目录 |

前端不连续三次 `write_unique_file_bytes`，避免半成品目录。单文件大小上限 1 MiB，超过拒绝。

网页版点保存时 toast「需要桌面端」，与上传文档一致。

## 7. 错误处理

- 取消对话框：静默返回
- 无内容 / 非桌面 / 路径不安全 / 写盘失败：toast，结果区内容不变
- 目录名冲突：自动加 `_2` 起，不弹覆盖确认

## 8. 测试

- 核心：空歌名、非法字符、超长名、扩展名剥离、README 不含正文
- Rust：目标已存在 → 得到 `_2`；写第二个文件失败 → 新目录被删掉
- 回归：`npm run test:ai-lyrics` 仍通过

## 9. i18n / 帮助

`zh.json` / `en.json` 增加保存按钮与成功/失败文案。帮助中心歌词页补一句：确认后可保存为本地作品文件夹，仍不上传音频。
